# 🖥️ אפיון MVP — מערכת סיוע למתאמות שירות

> מסמך אפיון טכני ופונקציונלי למערכת ה-MVP של רפורמת סל אישי בסיעוד.
> גרסה: 1.0 | תאריך: מרץ 2026 | סטטוס: טרום-התנעה

---

## 1. תמצית מנהלים

### הבעיה
מתאמות שירות בסיעוד עובדות עם טפסים ידניים, ללא כלים לזיהוי הדרדרות, וללא יכולת להתאים סל שירותים אישי. 44.6% מזכאי רמה 1 שהידרדרו לא קיבלו שום שירות מעבר לטיפול אישי (SDI=0).

### הפתרון
מערכת דיגיטלית שתומכת במתאמת השירות בכל שלבי העבודה: קליטת מטופל → הערכה תפקודית → המלצת סל מותאם → הפעלת שירותים → מעקב שוטף → התראות הדרדרות.

### היקף MVP
- 3-5 מתאמות שירות בפיילוט ירושלים
- 20-30 תיקי מטופלים
- 8 שבועות פיתוח

## 3. תהליך עבודה — User Flow של מתאמת שירות

```
┌─────────────┐    ┌──────────────┐    ┌───────────────┐    ┌──────────────┐
│  1. קליטה   │───▶│  2. הערכה    │───▶│ 3. המלצת סל  │───▶│ 4. אישור    │
│  פרופיל     │    │  תפקודית    │    │    מותאם      │    │  והתאמה     │
│  מטופל      │    │  + חברתית   │    │    אישית      │    │  ידנית      │
└─────────────┘    └──────────────┘    └───────────────┘    └──────────────┘
                                                                    │
┌─────────────┐    ┌──────────────┐    ┌───────────────┐            │
│ 7. עדכון    │◀───│ 6. התראות   │◀───│  5. מעקב     │◀───────────┘
│    סל       │    │  הדרדרות    │    │    שוטף      │
└─────────────┘    └──────────────┘    └───────────────┘
```

### שלב 1 — קליטת מטופל
- **קלט**: שם, ת.ז., גיל, מגדר, כתובת, רמת גמלה (1-6), מצב משפחתי
- **מקור נתונים**: ידני (בעתיד — אינטגרציה עם בטל"א)
- **תוצר**: כרטיס מטופל דיגיטלי

### שלב 2 — הערכה תפקודית וחברתית
- **כלי הערכה**: ADL (פעילויות יומיומיות), IADL (פעילויות מכשיריות)
- **ממדים**: תפקודי, חברתי, בריאותי, קוגניטיבי, טכנולוגי, סביבתי/דיור
- **שאלון**: מבוסס על תוצרי סדנת עיצוב שירות 11.2024
- **תוצר**: פרופיל תפקודי מספרי + תיאורי

### שלב 3 — המלצת סל מותאם
- **לוגיקה**: התאמה על בסיס רמת גמלה + פרופיל תפקודי + העדפות אישיות
- **מקור**: פרסונות EY + מיפוי שירותים מסדנת העיצוב
- **תוצר**: סל שירותים מומלץ עם חלוקה ל-6 ממדים
- **חשוב**: המתאמת יכולה לערוך, להוסיף, להסיר — ההמלצה היא נקודת פתיחה

### שלב 4 — אישור והתאמה
- **פעולה**: המתאמת סוקרת את ההמלצה, מתאימה לצרכים ספציפיים
- **אישור**: שמירת הסל הסופי + תיעוד הסיבות לשינויים
- **תוצר**: סל אישי מאושר

### שלב 5 — מעקב שוטף
- **תדירות**: ביקור/שיחה כל 2-4 שבועות (הגדרה לפי רמת סיכון)
- **תיעוד**: הערות מתאמת, שינויים במצב, משוב מטופל
- **תוצר**: היסטוריית טיפול מתועדת

### שלב 6 — התראות הדרדרות
- **מדדים**: RDI (שהות יחסית) + SDI (מגוון שירותים)
- **סף התראה**: RDI > 1.3 (פער ניכר) או SDI = 0 (אפס מגוון)
- **סוגי התראות**:
  - 🔴 דחוף: RDI > 1.5 + SDI = 0
  - 🟡 לבדיקה: RDI > 1.3 או SDI < 17
  - 🟢 תקין: RDI < 1.2 + SDI > 17

### שלב 7 — עדכון סל
- **טריגר**: התראה, שינוי מצב, בקשת מטופל/משפחה, הערכה תקופתית
- **פעולה**: עדכון הסל + תיעוד הסיבה + המלצה חדשה מהמנוע

## 5. מנוע ההמלצות — לוגיקה

### שלב MVP — מבוסס כללים (Rule-Based)

הלוגיקה מבוססת על מיפוי שנעשה בסדנת עיצוב שירות + פרסונות EY:

```
אם רמת_גמלה = 1-2:
    בסיס: טיפול אישי (לפי שעות זכאות)
    + אם בידוד_חברתי = גבוה → ליווי חברתי, מועדון יום
    + אם ADL > 2.5 → טכנולוגיה מסייעת (כפתור מצוקה, חיישנים)
    + אם קוגניטיבי < 2 → הפניה להערכה גריאטרית

אם רמת_גמלה = 3-4:
    בסיס: טיפול אישי + פעילות קהילתית
    + אם IADL < 2 → עזרה בניהול משק בית, קניות
    + אם רשת_תמיכה = חלשה → ליווי חברתי אינטנסיבי
    + אם נגישות_דירה = נמוכה → התאמות דיור

אם רמת_גמלה = 5-6:
    בסיס: טיפול אישי מורחב + סיעוד מקצועי
    + אם קוגניטיבי < 1.5 → מרכז יום לדמנציה
    + אם עומס_מטפל = גבוה → הקלה למטפל (respite)
    + טכנולוגיה מסייעת (חיישנים, מעקב GPS)
```

### שלב 2 — AI (לאחר MVP)
- למידה מתיקים קיימים: אילו סלים הובילו לתוצאות טובות
- חיזוי הדרדרות על בסיס פרופיל + היסטוריה
- התאמה אישית מתמדת

## 6. דשבורד מתאמת — מסכים עיקריים

### מסך 1: רשימת מטופלים
- טבלה עם: שם, גיל, רמת גמלה, RDI, SDI, סטטוס, תאריך מעקב אחרון
- סינון: לפי רמת גמלה, סטטוס התראה, תאריך
- מיון: לפי דחיפות (התראות קודם)
- חיפוש: שם / ת.ז.

### מסך 2: כרטיס מטופל
- פרופיל אישי + פרטי קשר
- הערכה אחרונה (6 ממדים — גרף עכביש)
- סל אישי נוכחי (רשימת שירותים לפי ממד)
- היסטוריית מעקב (ציר זמן)
- מדדים: RDI + SDI (גרף מגמה)
- התראות פתוחות

### מסך 3: בניית סל אישי
- המלצת מערכת (מוצגת כנקודת פתיחה)
- רשימת שירותים זמינים לפי ממד
- גרירה / בחירה של שירותים
- סיכום: מספר שירותים, כיסוי ממדים, SDI צפוי
- כפתור אישור + שדה הערות

### מסך 4: דשבורד מנהלת
- סה"כ מטופלים, חלוקה לפי רמת גמלה
- מפת חום: RDI × SDI (מטריצה)
- התראות פתוחות (מספר + רשימה)
- SDI ממוצע לפי רמת גמלה (גרף עמודות)
- מגמות: שינוי RDI/SDI לאורך זמן

### Stack טכנולוגי

| שכבה | טכנולוגיה | סיבה |
|------|-----------|------|
| Frontend | Next.js 14 + TypeScript | SSR, App Router, ביצועים |

| Backend | Node.js + Express + TypeScript | אקוסיסטם אחיד, מהירות פיתוח |

| ORM | Prisma | Type-safe, migrations, DX |
| Auth | NextAuth.js | פשוט, מאובטח, מוכן |
| Hosting | Vercel (frontend) + Railway/Render (backend + DB) | MVP מהיר, חינמי/זול |
