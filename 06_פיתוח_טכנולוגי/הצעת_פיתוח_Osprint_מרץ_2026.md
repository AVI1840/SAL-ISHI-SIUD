## רקע — מה הוחלט בפגישה

בפגישת יישור הקו עם שטראוס אסטרטגיה (מרץ 2026) התקבלו החלטות מפתח:

1. **סקופ**: כלי למתאמת השירות — לא מרקטפלייס ספקים
2. **מנוע התאמה**: פשוט בשלב ראשון — סינונים דיכוטומיים, לא AI
3. **תשתית דאטה**: איסוף נתונים לבניית מנוע לומד בעתיד
4. **שימוש רוחבי**: הכלי צריך להיות גנרי — נכויות, שיקום, אבטלה
5. **שותפות עיצוב**: מתאמות השירות הן שותפות עיצוב קריטיות

## ההצעה — 3 שלבים

### שלב 1: מוקאפ חי ב-Lovable (שבוע 1-2)

**מה:** בניית אבטיפוס עובד ב-Lovable על בסיס **Lovable 2 — מתאמת שירות** הקיים.

**למה Lovable 2:** זה בדיוק הכלי שהוחלט עליו ב-Osprint:
- דשבורד מתאמת שירות עם 28 מטופלים
- מדדי RDI/SDI מובנים (הנתונים האמיתיים מפיילוט ירושלים)
- תהליך קליטה ב-4 שלבים: פרטים → הערכה → המלצת סל → סיכום
- מעקב הדרדרות עם מטריצת RDI×SDI
- תיאום ספקים ודוחות

**התאמות נדרשות לאור החלטות Osprint:**

| החלטת Osprint | מה קיים ב-Lovable 2 | מה צריך לשנות |
|---------------|---------------------|---------------|
| מנוע התאמה פשוט | מנוע מבוסס כללים | ✅ עודכן — סינון דיכוטומי מפורט |
| תשתית איסוף דאטה | אין | ✅ עודכן — לוג החלטות מתאמת |
| שימוש רוחבי | ספציפי לסיעוד | ✅ עודכן — domain switcher + ארכיטקטורה גנרית |
| 286 משתתפים ירושלים | 12 מטופלי דמו | ✅ עודכן — 20 מטופלי דמו |
| מתאמת מנהלת רבים | 1:28 | ✅ מתאים |
| שירותים קהילתיים | קטלוג שירותים | ✅ מתאים — שירותים סביבתיים מודגשים |

**תוצר:** אפליקציה עובדת שניתן להציג במפגש Osprint הראשון. **הפרומפט כבר מעודכן ומוכן להרצה.**

## מנוע ההתאמה — גרסה פשוטה (כפי שהוחלט)

בהתאם להחלטת Osprint — לא מנוע AI, אלא סינון פשוט:

### שלב א: סינון דיכוטומי
```
אם (אזור_מגורים == אזור_שירות) AND
   (רמת_תפקוד בטווח שירות) AND
   (אין חסימה רפואית)
→ הצג שירות כמתאים
```

### שלב ב: תעדוף לפי כללים קשיחים
```
אם (SDI == 0) → העדף שירותים חברתיים (מניעת בידוד)
אם (RDI > 1.3) → העדף שירותים שמצמצמים הדרדרות
אם (גיל > 85 AND מגדר == נקבה) → דגל אדום (RDI=1.49)
```

### שלב ג: תשתית לעתיד
- כל החלטה של מתאמת מתועדת (מה הומלץ, מה נבחר, מה נדחה)
- כל שינוי מצב מתועד (RDI/SDI לפני ואחרי)
- הדאטה הזה יזין מנוע לומד בעתיד

## שימוש רוחבי — ארכיטקטורה גנרית

כפי שעלה בפגישה — הכלי צריך לשמש גם לנכויות, שיקום, אבטלה:

```
┌─────────────────────────────────────┐
│         מערכת מתאם שירות             │
│         (ליבה גנרית)                │
├──────┬──────┬──────┬───────────────┤
│סיעוד │נכויות│שיקום │ אבטלה         │
│      │      │      │               │
│RDI   │מדד X │מדד Y │ מדד Z         │
│SDI   │      │      │               │
│6 ממדים│ממדים │ממדים │ ממדים          │
│      │שונים │שונים │ שונים          │
└──────┴──────┴──────┴───────────────┘
```

**מה גנרי:**
- תהליך עבודה: קליטה → הערכה → המלצה → מעקב
- מבנה נתונים: פרופיל + ממדי הערכה + קטלוג שירותים + מעקב
- ממשק: דשבורד + רשימה + כרטיס + דוחות

**מה ספציפי לתחום:**
- ממדי ההערכה (6 ממדים בסיעוד, אחרים בנכויות)
- מדדי הדרדרות (RDI/SDI בסיעוד, מדדים אחרים בשיקום)
- קטלוג השירותים
- כללי ההתאמה

## נתוני מפתח מהפיילוט — לשילוב במוקאפ

### מדדי הדרדרות (נתונים אמיתיים)

**RDI לפי מגדר וגיל (רמה 1):**
| קבוצה | RDI | סטטוס |
|--------|-----|-------|
| גברים עד 74 | 0.74 | תקין |
| גברים 75-84 | 1.34 | פער ניכר |
| גברים 85+ | 1.03 | בנורמה |
| נשים עד 74 | 1.21 | פער קל |
| נשים 75-84 | 0.95 | בנורמה |
| **נשים 85+** | **1.49** | **חריג — אוכלוסיית יעד מועדפת** |

**SDI לפי רמת גמלה:**
| רמה | SDI=0 | SDI=17 | SDI≥33 | SDI ממוצע |
|-----|-------|--------|--------|----------|
| 1 | **44.6%** | 51.3% | 4.1% | 9.4 |
| 2 | 4.9% | 82.5% | 12.5% | 17.9 |
| 3 | 5.2% | 73.5% | 21.3% | 21.0 |

**תובנה מרכזית:** 44.6% מזכאי רמה 1 שהידרדרו לא קיבלו אף שירות נוסף (SDI=0). זו ההזדמנות הגדולה ביותר של הרפורמה.

### פיילוט ירושלים
- 286 משתתפים, רמות 1-3
- מתאמות שירות מבקרות, מבררות צרכים, בונות תוכנית אישית
- שירותים: סביבתיים, חברתיים, קהילתיים
- מטרה: מעבר ממצב סטטי לדינמי ועצמאי
